# 4月利用開始時の初期車両登録 運用マニュアル

このマニュアルは、4月に新規利用を開始した車両について、最初の半期バッチ対象になるまでの空白期間に行う手動登録手順をまとめたものです。

---

# 基本編 ― まず読んでください

## 1. このマニュアルの目的

車両リース契約更新システムは**半期バッチ（3月便・9月便）**で契約更新を処理しますが、4月に新規利用を開始した場合、最初のバッチ対象（9月便）になるまで数か月の空白期間が発生します。

この期間中、新規車両を正しくシステムに登録し管理するための手動手順を説明します。

| 利用開始月 | 最初のバッチ対象 | 空白期間 |
| --- | --- | --- |
| **4月** | 9月便（4月〜9月満了分） | 約5か月 |
| **10月** | 3月便（10月〜3月満了分） | 約5か月 |

**このマニュアルの対象は主に4月利用開始のケースですが、10月利用開始の場合も同様の手順で登録できます。**

---

## 2. 登場人物と役割

| 役割 | 誰か | やること |
| --- | --- | --- |
| **台帳管理担当** | 車両データの管理者 | 車両一覧への新規車両の登録を行う |
| **運用管理者** | システム管理者 | 登録内容の確認と不備チェックを行う |

---

## 3. 車両一覧シートへの新規車両登録手順

### 3.1 登録前の準備

1. 対象のスプレッドシートを開く
2. 「**車両一覧**」シートを選択する
3. リース会社から届いた契約書・車両情報を手元に用意する

### 3.2 必須項目の入力

車両一覧シートの最終行の下に、新規車両の情報を入力します。以下の項目は**必須**です。

| 項目名 | 説明 | 入力例 |
| --- | --- | --- |
| `vehicleId` | 車両を一意に識別するID。**既存のIDと重複しないこと** | `V-2026-0042` |
| `管理部門` | 車両を管理する部門名 | `東京本部` |
| `使用者` | 車両の使用者名 | `山田太郎` |
| `車種` | 車両の車種名 | `プリウス` |
| `登録番号` | ナンバープレートの登録番号 | `品川 500 あ 1234` |
| `契約開始日` | リース契約の開始日 | `2026/04/01` |
| `契約満了日` | リース契約の満了日 | `2029/03/31` |
| `リース料` | 月額リース料（税込） | `45000` |
| `リース会社` | 契約先のリース会社名 | `オリックス自動車` |

### 3.3 入力ルール・注意点

- **vehicleId は手動で採番する：** 既存の車両一覧で最大のIDを確認し、連番で付与してください
- **日付の形式は `YYYY/MM/DD`：** `2026/04/01` のように西暦で入力してください。`R8/4/1` のような和暦は使わないでください
- **リース料は数値のみ：** カンマや「円」は入れず、半角数字で入力してください（例：`45000`）
- **行を途中に挿入しない：** 必ず最終行の下に追加してください。途中挿入するとバッチ処理で不整合が起きる可能性があります
- **ヘッダ行を変更しない：** 列名やヘッダの順序を変えるとシステムが正しく動作しません

---

## 4. 登録後の確認手順（要入力シートでの不備チェック）

新規車両を登録したら、不備がないか確認します。

1. メニュー → 手動ステップ →「**車両一覧同期（要入力更新）**」を実行する
2. 「**要入力**」シートを確認する
3. 登録した車両が「要入力」に表示されていなければ不備なし

**「要入力」シートに表示された場合：**

- 表示された不備内容を確認し、車両一覧シートの該当行を修正する
- 再度「車両一覧同期（要入力更新）」を実行し、不備が解消されたことを確認する

よくある不備の例：

| 不備内容 | 原因 | 対処 |
| --- | --- | --- |
| 契約満了日が空 | 満了日が未入力 | 契約書を確認して入力する |
| vehicleId が重複 | 既存車両と同じIDを付けた | IDを採番し直す |
| 日付形式エラー | 和暦や不正な形式で入力した | `YYYY/MM/DD` 形式に修正する |

---

## 5. バッチ対象になるタイミング

登録した車両がバッチ処理の対象になるタイミングは以下の通りです。

| 契約満了日の範囲 | 対象バッチ | バッチ実行時期 |
| --- | --- | --- |
| 4月1日 〜 9月30日 | **9月便** | 9月上旬 |
| 10月1日 〜 翌年3月31日 | **3月便** | 3月上旬 |

**例：** 4月に利用開始し、契約満了日が `2029/03/31` の車両は、**2029年3月便**で初めてバッチ対象になります。

それまでの間は車両一覧に登録されているだけの状態ですが、バッチ対象時期が来れば自動的に抽出されるため、追加の操作は不要です。

# リファレンス編 ― 困ったときに見てください

## よくある質問

| 質問 | 回答 |
| --- | --- |
| **バッチ対象になる前に契約内容が変わったら？** | 車両一覧シートの該当行を直接修正してください。バッチ起票前であればそのまま反映されます |
| **誤って登録した車両を削除したい** | 車両一覧シートの該当行を削除してください。ただし、既にバッチ対象になっている場合は運用管理者に相談してください |
| **vehicleId の採番ルールは？** | `V-YYYY-NNNN` の形式で、YYYY は年度、NNNN は連番です。既存の最大番号の次を使ってください |
| **複数台を一度に登録してもよい？** | はい。1台ずつ最終行に追加してください。まとめて登録した後、1回だけ「車両一覧同期（要入力更新）」を実行すればまとめてチェックできます |
| **登録後すぐにバッチ処理を走らせたい** | 半期一括実行で対応できますが、通常は半期の時期まで待ってください。テスト目的の場合は運用管理者に相談してください |

---

## トラブル対応

| 症状 | 確認すること | 対策 |
| --- | --- | --- |
| **「要入力」に不備が残り続ける** | 車両一覧の該当行で必須項目が正しく入力されているか | 入力値と形式を見直して再度同期を実行 |
| **バッチ対象時期なのに車両が抽出されない** | 契約満了日がバッチ対象期間内か、vehicleId が正しいか | 満了日と対象期間を照合して修正する |
| **登録した車両が車両一覧から消えた** | 他のユーザーが誤って削除していないか | スプレッドシートの変更履歴で復元する |
