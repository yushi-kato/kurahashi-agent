## 1. このシステムでできること

一言で言うと：「**満了車両の更新/解約を、専務承認付きで一括処理する**」

具体的には、次のことができます。

1. 半期ごとの対象車両を自動抽出する
2. 本部長・副本部長へ一括で確認依頼を出す
3. 締切前に未完了時だけリマインドを送る
4. 全件確認完了で専務へ承認依頼を送る
5. 専務の承認後、マスターへ反映する

---

## 2. 登場人物と役割

| 役割 | 誰か | 主な作業 |
| --- | --- | --- |
| **本部長・副本部長** | 各部門の責任者 | 満了車両について「更新」か「解約」かを判断する |
| **専務** | 全社の決定権者 | 本部回答を一括して「承認」か「差戻し」を判断する |
| **村田主任** | 実務担当者 | 承認済み車両について、新契約日や解約完了を入力する |
| **運用管理者** | システム管理者 | 通知先や締切日などを設定する |
| **台帳管理担当** | 車両データの管理者 | 車両一覧（元台帳）の事実データを管理する |

## 3. 1年間のスケジュール

このシステムは**年2回**、3月と9月に稼働します。

### 3月便と9月便の違い

| 便名 | 送付日 | 対象期間 | 締切 |
| --- | --- | --- | --- |
| **3月便** | 3月1日 | 前年10月1日 〜 当年3月31日満了分 | 3月31日 |
| **9月便** | 9月1日 | 4月1日 〜 9月30日満了分 | 9月30日 |

## 4. 各担当者の操作手順

### 4.1 本部長・副本部長（一次確認者）

#### やること

1. メールで送られるリンクから「確認用シート」を開く
2. 各車両について「本部回答」を入力する
   - `更新`：契約を継続する
   - `解約（入替）`：入替のために解約する
   - `解約（満了）`：満了のため解約する
3. 入力が終わった行の「回答確認済み」にチェックを入れる

#### 注意点

- **全行にチェックが入らないと、専務依頼が送られません**
- 一部未入力でも、専務への進行が止まります

---

### 4.2 専務（承認者）

#### やること

1. メールで送られるリンクから「確認用シート」を開く
2. 各車両について「専務判断」を入力する
   - `承認`：本部回答通りに進める
   - `差戻し`：本部へ再検討を求める
3. 必要に応じて「専務コメント」を入れる

#### 注意点

- 専務判断の列は保護されており、専務以外は編集できません
- 差戻しの場合、本部長・副本部長が再回答する必要があります

---

### 4.3 村田主任（反映担当）

#### やること

承認済みの車両について、次を入力します。

**更新の場合：**
- `新契約開始日`
- `新契約満了日`

**解約の場合：**
- `解約完了` にチェック

入力が終わったら、自動または手動で「マスター反映」が実行されます。

---

### 4.4 運用管理者

#### 定期的な作業

- 半期ごとの「設定」確認
- 通知ログの確認

#### 半期便ごとの作業フロー

メニュー「半期一括実行」から次をまとめて実行できます。

1. スキーマ同期
2. 車両一覧同期（要入力更新）
3. 半期バッチ起票
4. 初回通知送信
5. リマインド送信（条件一致時）
6. 専務依頼送信（全件確認後）

## 5. 運用管理者向け設定

### 5.1 スプレッドシートのタブ一覧

| タブ名 | 役割 | 主に見る/触る人 |
| --- | --- | --- |
| **設定** | 通知先や締切日などの運用ルールを決める | 運用管理者が設定・変更 |
| **車両一覧** | 元台帳であり、同時に最終反映先でもある唯一の正本 | 台帳管理担当が事実データを入力<br>システムが反映結果を書く |
| **通知バッチ** | 半期便の進捗を記録する台帳 | 運用管理者が進捗確認 |
| **本部長副本部長確認_YYYYMMDD** | 回答と承認の入力画面 | 本部長・副本部長、専務、村田主任が入力 |
| **要入力** | 元台帳の不備（満了日なし等）を検出したログ | 台帳管理担当が修正対象を確認 |
| **通知ログ** | メール送信の記録 | 運用管理者が送信結果を確認 |

### 5.2 「設定」タブの必須項目

「設定」タブで、最低限次の項目を確認してください。

| 項目名 | 説明 | 例 |
| --- | --- | --- |
| `本部長副本部長_通知先To` | 初回通知・リマインドの送付先 | メールアドレス（カンマ区切りで複数可） |
| `専務_通知先To` | 専務承認依頼の送付先 | メールアドレス |
| `専務_通知先Cc` | 専務依頼のCC（任意） | メールアドレス |
| `半期送付日_3月` | 3月便の送付日 | 3月1日 |
| `半期送付日_9月` | 9月便の送付日 | 9月1日 |
| `回答期限_3月` | 3月便の締切日 | 3月31日 |
| `回答期限_9月` | 9月便の締切日 | 9月30日 |
| `リマインド_期限前日数` | 締切何日前にリマインドを送るか | 10 |
| `通知_メール送信` | メールを実際に送るかどうか | TRUE（送る）/ FALSE（送らない） |
| `自動進行_有効` | 自動進行モードをONにするか | TRUE / FALSE |
| `自動進行_定期実行_有効` | 定期トリガーで自動進行を動かすか | TRUE / FALSE |
| `自動進行_編集連動_有効` | 確認用シート編集時に自動進行するか | TRUE / FALSE |
| `自動進行_専務判断反映_有効` | 専務判断反映を自動で行うか | TRUE / FALSE |
| `自動進行_マスター反映_有効` | マスター反映を自動で行うか | TRUE / FALSE |

## 6. 自動進行モードの説明

### 6.1 自動進行モードとは

運用管理者のメニュー操作を減らすため、**条件を満たすと自動的に次のステップに進む**機能です。

- 確認用シート生成
- 初回通知送信
- リマインド送信（条件一致時）
- 専務依頼送信（全件確認後）
- 専務判断反映
- マスター反映

### 6.2 自動進行のトリガー

| トリガー種別 | 説明 |
| --- | --- |
| **定期トリガー** | 1時間ごとに実行され、条件を満たす処理を前進させます |
| **編集連動トリガー** | 確認用シートや車両一覧が編集された時に実行されます |

### 6.3 自動進行の判定ルール

| 処理 | 自動で進む条件 |
| --- | --- |
| **リマインド送信** | 期限前日数に到達 かつ 未完了行あり かつ 当バッチで未送信 |
| **専務依頼送信** | 全行で「本部回答」入力済み かつ 全行で「回答確認済み」チェック済み |
| **マスター反映** | 専務判断が「承認」 かつ 必須入力完了（新契約日 または 解約完了チェック） |

## 7. 困ったときの対応

### 7.1 メールが送られない

**確認すること：**

1. 「通知ログ」シートを確認する
   - 送信結果やスキップ理由が記録されています
2. 「設定」タブの次を確認する
   - `通知_メール送信` が `FALSE` になっていないか
   - `本部長副本部長_通知先To` が空になっていないか

**対策：**
- 設定を修正してから再実行してください

### 7.2 専務依頼メールが来ない

**確認すること：**

確認用シートで次を確認してください。

- `本部回答` の空欄がないか
- `回答確認済み` の未チェックがないか

**対策：**
- 未入力・未チェックを埋めてから時間を置いてください

### 7.3 マスター反映されない

**確認すること：**

確認用シートで次を確認してください。

- `専務判断` が `承認` になっているか
- 更新行：`新契約開始日` と `新契約満了日` が入っているか
- 解約行：`解約完了` にチェックが入っているか

**対策：**
- 必須項目を埋めてから、手動で「マスター反映（最新バッチ）」を実行してください

---

## 8. やってはいけないこと

システムの整合性を保つため、次の操作は避けてください。

- 「通知バッチ」と確認用シートのヘッダ名を変更しない
- `vehicleId` / `batchId` を手で書き換えない
- 専務判断列の保護設定を外さない
- 旧導線（フォーム運用）に戻す目的で列や設定を独自変更しない
